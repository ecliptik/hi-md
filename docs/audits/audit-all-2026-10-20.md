# Minidisc Full Health Check: 2026-10-20

## Scope

- Scope: full project audit. `Minidisc/` holds 397 non-test Swift files. The 510 you quoted includes `MinidiscTests/` and `MinidiscUITests/`.
- Static analysis only. The app was not built, run or profiled, so every performance and energy estimate needs Instruments to confirm.
- `scratch/` was empty at the start of the run. Everything below is therefore a new baseline (see Regression Check).
- 19 auditors ran in parallel. Findings are reported at each auditor's severity. Where several auditors hit the same code, the cross-cutting section below merges them.
- No user emphasis or exclusions were given. Ordering is severity-first.

## Cross-cutting findings (deduplicated across auditors)

Each item was reported by two or more auditors.

### X1. Per-track download commit does an O(albums x tracks) SwiftData recount on the MainActor
- Location: `Minidisc/Services/Implementations/DownloadService.swift:283-290`, `:304`, `:323`, `:533-567`, `:653-654`, `:762-763`.
- Reported by: swiftdata H3, swift-performance C3, concurrency H3.
- The work runs in `MainActor.run` for every committed song. It fetches every `DownloadedTrack`, `DownloadedAlbum` and `DownloadedPlaylist` and filters per album.
- Fix: group once with `Dictionary(grouping:)`, or recount only the affected album and playlist with a predicate `fetchCount`. Move the writes off the MainActor into an actor-owned `ModelContext`.

### X2. Local-music library is rescanned and re-persisted every 30 s while the app is active
- Location: `Minidisc/Views/Main/RootView.swift:12-18`, `Minidisc/Services/LocalMusic/LocalMusicLibrary.swift:145-201`, `:217-241`, `:320-334`.
- Reported by: energy H1, concurrency H2, swift-performance H7, architecture M9.
- Each pass walks the tree with `NSFileCoordinator`, re-sorts, and atomically rewrites `index.json` even when nothing changed. It also runs when no folders are configured.
- The scan occupies the `LocalMusicStore` actor that `access(_:)` needs for local playback start.
- Fix: refresh once on scene-active, after `add`, and on pull-to-refresh. Skip when there are no folders. Skip `persist` when the snapshot is unchanged.

### X3. Whole-collection Sets are rebuilt per row in song lists
- Location: `Minidisc/Views/Browse/PlaylistDetailView.swift:961-966, 990-992, 1016, 1028`, `AlbumDetailView.swift:943-981`, `SearchView.swift:330-344`, `ArtistDetailView.swift:658-678`, `RecentlyAddedView.swift:95`.
- Reported by: swiftui-performance C1/H1, swiftdata H2.
- `favoriteSongIds` and `downloadedSongIds` are computed properties over unfiltered `@Query` results, evaluated inside the row builder.
- Fix: build each Set once per body or in `@State`. Filter the queries by type and server.
- Related: `SongsListView.swift:101, 167-169` runs a synchronous `fetchCount` per row through `FavoritesService.isFavorite` (swiftui-performance H2, swift-performance H8).

### X4. Big-library sorting, grouping and indexing runs inside view bodies
- Location: `AlbumsListView.swift:12-15, 84-85, 109, 124-126`, `ArtistListView.swift:47-64`, `SongsListView.swift:45-65` (offline path), `LocalMusicBrowseView.swift:35-76`, `LocalMusicView.swift:27-42`, `FavoritesView.swift:52-58`, `DownloadedView.swift:48-77`, `SearchView.swift:147-175`, `AlphabetJumpBar.swift:69-90`.
- Reported by: swift-performance C1/C2/H6/H8, swiftui-performance H3-H8, architecture H6/H8/H9/M15.
- `localizedStandardCompare` sorts of thousands of items run several times per body. Alphabet letters are recomputed per item on every drag tick.
- Fix: move derivation into view models and compute it off-main with `@concurrent`, as `SongsListViewModel` already does. Precompute collation keys and a letter-to-first-index map.

### X5. Value-based `HomeDestination` links are dead in the Discover stack and in sheet NavigationStacks
- Location: Discover stack at `MainTabView.swift:57-59` and `DiscoverView.swift:79`. Sheets at `FullPlayerView.swift:511-519` and `ArtistDetailView.swift:696-704`. Dead links at `ArtistDetailView.swift:384, 434, 805` and `AlbumDetailView.swift:639`.
- Reported by: swiftui-nav H1/H2, ux-flow H1, architecture M1.
- Taps do nothing. This affects Discover, then Wrapped, then artist/album detail, and the player's "Go to Album" sheet.
- Fix: extract the `HomeDestination` resolver into one shared modifier. Apply it to every tab stack and every sheet stack. `SearchView.swift:110` currently falls back to `EmptyView()`.

### X6. Wrapped story player cannot be used with VoiceOver or Switch Control
- Location: `Minidisc/Views/Wrapped/Story/WrappedStoryPlayerView.swift:71-95, 99-142, 230-241`.
- Reported by: accessibility C1, ux-flow H3.
- Slides auto-advance every 5 s. Navigation exists only as a full-screen `DragGesture` layer with no accessibility actions. The close button has no label.

### X7. Toasts and error messages are never announced
- Location: `ToastService.swift:48-62`, `ToastView.swift:77-98`, `ConnectionErrorView`. No `AccessibilityNotification` exists anywhere in the app.
- Reported by: accessibility H1, ux-flow H2.

### X8. Custom auth headers are re-sent on cross-origin redirects
- Location: `CustomHeadersTransport.swift:19`, `BackgroundDownloadTransport.swift`, `DownloadQueueController.swift:243-244`, `DownloadService.swift:974-979`, `PlayerService.swift:1027, 4039`, `LidarrClient.swift:208-211`.
- Reported by: networking M, security M.
- `ServerConnection.authorizationHeaders(for:)` scopes headers to the right origin for the first request. URLSession keeps non-`Authorization` custom headers on redirects, and no redirect delegate exists.

### X9. Credential-bearing integration endpoints accept cleartext or any scheme with no warning
- Location: `ListenBrainzSettingsViewModel.swift:140-145`, `ListenBrainzClient.swift:31, 304`, `LidarrClient.swift:32-34, 208-211`, `AudioMuseClient.swift:75-77, 141-143`.
- Reported by: security H1, networking M.
- ATS is off app-wide, so the ListenBrainz token, the Lidarr API key and the AudioMuse bearer token can go out in plaintext. Only the Subsonic form warns about `http://`. The ListenBrainz field accepts `ftp:` and `file:`.

### X10. Downloads and artwork cache live in Documents, are backed up, and are partly unbounded
- Location: `DownloadService.swift:214-218`, `ArtworkImageCache.swift:483-493, 699-708`, `BackgroundDownloadTransport.swift:45`, `AppContainer.swift:341-353`, `LocalMusicLibrary.swift:271-277`.
- Reported by: storage H1/H2/M1-M3, security M.
- Only `OfflineFavoritesStore` sets `isExcludedFromBackup`. The `@thumb`/`@hero` streaming tier files are never evicted.

### X11. Unbounded in-memory caches and no memory-warning handling
- Location: `ArtworkLoader.swift:12, 46, 50`, `LidarrCoverImage.swift:5-11`, `ArtworkImageCache.swift:157, 934-961`.
- Reported by: memory H1/H2/M1, swift-performance M4, swiftui-performance M15.
- Nothing responds to `didReceiveMemoryWarning`. The cache is capped by count (110), and a hero image decodes to about 5.8 MB.

### X12. Playlist song downloads spawn one unstructured Task per song
- Location: `PlaylistService.swift:258-262, 308-312`, plus `DownloadQueueController.swift:97-133, 230-264, 332-337`.
- Reported by: concurrency H5, swift-performance H3, energy M4, memory L.
- Each enqueue rewrites the whole journal, so a 500-song playlist causes about 2N journal rewrites. `retryMissingPlaylistDownloads` runs this on every launch for partly downloaded playlists.

### X13. Launch path does heavy MainActor work
- Location: `MinidiscApp.swift:217-271`, `AppContainer.swift:65-85, 363-544`, `NowPlayingService.swift:106-110`.
- Reported by: concurrency H1/H4/M8, swift-performance H5.
- `makeContainer` awaits `restoreSession()`, which can wait on a network artwork fetch (up to about 10 s). It also runs cover-art GC, file migrations and a content sniff of every download on the MainActor.

### X14. Persisted JSON stores do not recover from decode failures
- Location: `LocalMusicLibrary.swift:94-95`, `DownloadQueueController.swift:72-76`, `OfflineFavoritesStore.swift:34-41`, `ListenBrainzService.swift:142-162`, `PlaybackSession.swift:33, 45, 61`.
- Reported by: codable H1-H4/M5, swiftdata M.
- A failed decode becomes an empty value that is later overwritten, or throws forever. The persisted files embed SwiftSonic DTOs with no schema version.

### X15. Server removal leaves its data behind
- Location: `ServerService.swift:87-129`.
- Reported by: storage M6, swiftdata M.
- Downloads, favorites, pins, stats, cache rows and queue jobs for the server survive. No UI calls `removeServer`.

### X16. Smaller overlaps
- `minidisc://` URL scheme is registered with no handler: `Info.plist:20-32` (nav C1, security L3).
- Local-files onboarding is a one-way door (ux C1) and no sign-out or remove-server UI exists (ux M3).
- Missing `3B52.1` FileTimestamp reason for user-granted folders: `PrivacyInfo.xcprivacy:12` (security M).
- Wrapped `MeshGradientBackground` repeats animations forever with no visibility gating: `MeshGradientBackground.swift:12-17` (energy M2, swiftui-performance M14).
- Lyrics blur per line (energy L5, swiftui-performance L4, accessibility M3).
- `ImmersiveCoverHero` and `PlaylistArtworkHeader` read `frame(in: .global)` on every scroll frame (layout M2, swiftui-performance M13).
- `DominantColorExtractor` rewrites the whole UserDefaults dictionary per cover (storage M5, swiftui-performance M11, swift-performance M7, memory L).
- `DispatchQueue.main.asyncAfter` sheet sequencing in 13 places (modernization, concurrency L1).
- `EditPlaylistSheet.swift` is never instantiated but is copy-pasted into the other two playlist sheets (architecture H1, simplify, ux L2).
