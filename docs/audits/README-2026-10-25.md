Several findings appear in more than one audit:
- offline search scoring
- placeholder detection on the MainActor
- the `ArtworkImageCache` cost cap
- per-song tasks and actor hops for downloads
- `DominantColorExtractor`

## Suggested order

1. **Correctness and regressions:**
   - The gapless preload is never retried after a failed resolve (concurrency H3).
   - Lyrics tracking freezes after a track change, a regression from the keep-alive change (memory M-3).
   - Path traversal through server IDs (security H1).
   - The privacy manifest is missing SystemBootTime and 3B52.1 (security H2, M3).
   - The Winamp `region.txt` and M3U crashes (security M7, M8), fixed before that code merges.
2. **Performance, measured before and after:**
   - Queue snapshot on track changes (SwiftUI C1).
   - Offline and online search ranking (Swift C1/H1, SwiftUI H5).
   - The cover mount path and placeholder detection off the MainActor (SwiftUI H4, Swift H2, concurrency M6).
   - `Array(enumerated())` copies (SwiftUI H3).
   - `SongSelectionSheet` (SwiftUI H2).
   - Auto-extend and queue saves on every skip (Swift H5, H6).
   - The `LidarrImageStore` cap and memory-warning trimming (memory H-1, M-1).
3. **Launch and the MainActor:**
   - Launch waits on an artwork fetch, and runs SwiftData on the MainActor (concurrency H1, H2).
   - Batch playlist downloads (concurrency C1).
4. **Tests:**
   - Remove the launch-test multiplier (testing H5).
   - Recovery `startupGrace` (testing H2).
   - The queue-drag test (testing H1).
   - The five permanently red scenarios (testing H4).
5. **UX and accessibility:**
   - Widget link names (accessibility H4).
   - Widget URLs on a cold launch (UX H2).
   - Dark-mode accent contrast (accessibility H1, H2).
   - Player toolbar state (accessibility H3).
   - The rest of the mediums.
